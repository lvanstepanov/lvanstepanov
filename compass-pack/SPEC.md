# KASE Compass — спецификация MVP

Версия данных: размещения с 09.01.2026 по 19.10.2026, аукционы ГЦБ по 20.10.2026. Эталонная реализация: `reference/compass_reference.html`. Если что-то здесь расходится с эталоном, прав эталон.

## 1. Продукт

**Для кого.** Казначейства эмитентов (МФО, лизинговые компании, банки, корпорации, квазигосударственные компании) и андеррайтеры.

**Боль.** Перед выпуском облигаций эмитент не знает, какой купон поставить. Публичные данные KASE разбросаны по сотням сообщений об итогах размещений.

**Решение.** Ориентир купона = доходность ГЦБ того же срока на сегодня + спред, который этот эмитент (или его тип) платил на KASE. К ориентиру — похожие сделки со ссылками, состав покупателей, цена ошибки в тенге и честная проверка точности на истории.

**Чего нет в продукте:**
- чат-бота;
- ИИ-ассистента;
- генерации текста моделью;
- инвестиционных рекомендаций («купите», «продайте»);
- выдуманных данных;
- логотипа KASE: это концепт, а не официальный сервис.

## 2. Данные (`data/compass_data.json`)

```
{ "asof": "2026-10-19", "deals": [...187], "gcb": [...95], "bt": [...110], "stick": {...} }
```

### 2.1 `deals` — размещения (одна строка = одно сообщение KASE об итогах)

| Поле | Тип | Смысл |
|---|---|---|
| `id` | число | ID сообщения KASE. Ссылка: `https://kase.kz/ru/information/news/show/{id}` |
| `d` | `YYYY-MM-DD` | дата размещения |
| `iss` | строка | эмитент (короткое имя) |
| `seg` | код | тип эмитента: `quasi`, `bank`, `corp`, `mfo`, `leas`, `ifi` (см. 2.5) |
| `tk` | строка | торговый код выпуска |
| `ccy` | `KZT` / `USD` / `RUB` | валюта выпуска |
| `ten` | число или null | срок до погашения на дату размещения, лет |
| `met` | `спецторги` / `подписка` | способ размещения |
| `prt` | число или null | число участников |
| `bid` | число или null | число активных заявок |
| `cov` | число или null | спрос к предложению, %; null — KASE не опубликовала |
| `bmin`, `bmax` | число или null | минимальная и максимальная ставка в заявках, % |
| `fin` | число или null | итоговая ставка размещения, % (для `knd = маржа` — маржа к плавающей базе) |
| `knd` | `купон` / `доходность` / `маржа` / null | что означает `fin` |
| `vol` | число | размещённый объём, млрд ₸ (USD пересчитаны по 475,09 ₸) |
| `src` | `спрос` / `размещение` / null | от чего считаются доли покупателей; null — доли не раскрыты |
| `ret` | % или null | физлица |
| `bank` | % или null | банки |
| `inst` | % или null | другие институциональные инвесторы |
| `bdo` | % или null | брокеры-дилеры |
| `oth` | % или null | прочие юрлица |
| `leg` | % или null | юрлица без разбивки |
| `ini` | строка | организатор (андеррайтер) |
| `gcb` | число или null | доходность ГЦБ того же срока на дату сделки, % (кривая ±45 дней, см. 3.2) |
| `spr` | число или null | спред = `fin − gcb`, п. п. Есть только у 145 сделок: тенге, фиксированная ставка |

Если `src` не null, а доля категории null, считай её равной 0.

### 2.2 `gcb` — аукционы Минфина (МЕОКАМ, МЕУКАМ, МЕККАМ)

`{ "d": "2026-10-20", "y": 14.72, "t": 2.8 }`:
- `d` — дата аукциона;
- `y` — доходность, %;
- `t` — срок до погашения, лет.

### 2.3 `bt` — проверка на истории (110 размещений в тенге с фиксированной ставкой, 03.03–19.10.2026)

`{ d, tk, iss, seg, t, rate, A, B, C, D, own }`:
- `t` — срок;
- `rate` — фактическая ставка;
- `own` — у эмитента была прошлая сделка со спредом.

Прогнозы четырёх методов, %:

| Метод | Формула | Когда пусто |
|---|---|---|
| `A` | ГЦБ того же срока + медианный спред типа за 180 дней | — |
| `B` | медиана ставок того же типа за 180 дней | — |
| `C` | прошлый купон эмитента | null у новых эмитентов |
| `D` (Compass) | ГЦБ + прошлый спред эмитента; у новых эмитентов `D = A` | — |

**Без заглядывания вперёд.** Для каждой сделки использовались только данные до её даты:
- кривая ГЦБ строилась по аукционам за 60 дней **до** сделки;
- спред и ставки типа брались за 180 дней до сделки;
- сделка попадала в проверку, если у её типа было не меньше 5 сделок за эти 180 дней.

Сайт не пересчитывает `bt`, а только агрегирует его (3.13).

### 2.4 `stick` — новые выпуски с купоном прошлого выпуска

`{ seg: { n, same } }`:
- `n` — новых выпусков (тикер раньше у эмитента не встречался), у эмитента которых было размещение в другой, более ранний день не раньше чем за 365 дней;
- `same` — из них с той же ставкой, что у последнего такого размещения.

Доразмещения уже обращающихся выпусков и транши в один день не считаются. Расчёт — по 145 сделкам в тенге с фиксированной ставкой.

## 3. Формулы

### 3.1 Базовые
- `clip(t) = min(max(t, 0.5), 15)`.
- `quantile(v, p)` — линейная интерполяция, как `PERCENTILE.INC` в Excel и `numpy.quantile`. Сортируем v; `h = (n − 1)·p`; результат `v[⌊h⌋] + (v[⌈h⌉] − v[⌊h⌋])·(h − ⌊h⌋)`.
- Медиана = `quantile(v, 0.5)`.

### 3.2 Кривая ГЦБ
- `curveAt(date, win = 45)` — МНК по точкам `gcb`, у которых `|d − date| ≤ win` дней.
- Модель: `y = a + b·ln(clip(t))`. При n < 3 возвращает null.
- Коэффициенты:
  - `b = (n·Σxy − Σx·Σy) / (n·Σx² − (Σx)²)`, где `x = ln(clip(t))`;
  - `a = (Σy − b·Σx) / n`.
- `yieldAt(c, t) = c.a + c.b·ln(clip(t))`.
- Текущая кривая: `CNOW = curveAt(asof)`. Это 20 аукционов, последний — 20.10.2026.

### 3.3 Статистика спредов по типам
Для каждого типа берём `spr` всех его сделок со спредом и считаем `n`, `p25`, `p50`, `p75` через `quantile`.

### 3.4 Ориентир, режим «Уже был на KASE» (повторный эмитент)
1. `hist` — сделки эмитента со `spr`, отсортированные по дате, при равной дате — по `id`. `last = hist[последний]`.
2. `g = yieldAt(CNOW, T)`, где T — выбранный срок.
3. `keep = g + last.spr` — сохранить прошлый спред.
4. `rep = last.fin` — повторить прошлый купон.
5. Коридор: `lo = min(keep, rep)`, `hi = max(keep, rep)`, `mid = (lo + hi) / 2`.
6. Сдвиг рынка: `dG = yieldAt(CNOW, last.ten) − last.gcb`. Если `|dG| ≥ 0,3`, показываем плашку.
   - Если `dG < 0` («Рынок сдвинулся, а купон?»): «С {дата last} доходность ГЦБ на {срок last} снизилась на {−dG} п. п. Повторив купон {rep}%, эмитент заплатит спред {rep − g} п. п. вместо прошлых {last.spr}: {couponMln(vol, |rep − keep|)} в год на {vol} млрд ₸.» Затем одна фраза из `stick`:
     - для лизинга, МФО и корпораций — по их сумме: «У лизинга, МФО и корпораций 13 из 14 новых выпусков 2026 года вышли с купоном прошлого выпуска.»;
     - для остальных типов — по своему типу, если `n ≥ 3`: «У банков 7 из 15 новых выпусков…»; иначе фразы нет.
   - Если `dG > 0` («Рынок подорожал»): «…выросла на {dG} п. п. Прежний купон может не собрать спрос: сохранить спред — это {keep}%.»

Список эмитентов в выпадающем списке — все, у кого есть хотя бы одна сделка со `spr`, по алфавиту (ru). Подсказка под списком: «{Тип} · {n} размещений в тенге с фиксированной ставкой в 2026 году».

### 3.5 Ориентир, режим «Новый эмитент»
1. `g = yieldAt(CNOW, T)`.
2. Коридор: `lo = g + p25`, `mid = g + p50`, `hi = g + p75` по статистике выбранного типа.
3. Плашка «Широкий коридор — честно»: «По одному типу эмитента ставку точно не угадать: внутри сегмента ставки отличаются на несколько п. п. В полной версии коридор сузят кредитные рейтинги и кривая спроса.»

### 3.6 Деньги
- `couponMln(vol_млрд, rate_%) = vol × rate × 10` — купон в год, млн ₸.
- Строка под ориентиром: «0,1 п. п. на {vol} млрд ₸ — {couponMln(vol, 0,1)} купона в год. Разница между краями коридора — {couponMln(vol, hi − lo)} в год.»

### 3.7 Сравнение двух вариантов
- **Вариант A:** выбранный срок, ставка = `mid`.
- **Вариант B:** срок по умолчанию `min(15, T + 1)`, ставка = `mid` того же режима для этого срока. Оба поля B редактируются.
- Строки таблицы:
  - срок;
  - ставка;
  - купон в год = `couponMln(vol, ставка)`;
  - купон за весь срок = купон в год × срок.
- Вывод под таблицей: «Вариант B дороже/дешевле на {разница} в год, зато деньги на {разница сроков} дольше/короче». Если разница меньше 0,5 млн ₸ — «Купон в год почти одинаковый».

### 3.8 Сопоставимые сделки
Окно — сделки со `spr` за 180 дней: `d ≥ asof − 180 дней`.
- **Повторный эмитент:**
  - 4 последние свои сделки со `spr`, новые сверху. Для своих сделок окно в 180 дней не действует;
  - плюс 5 сделок того же типа других эмитентов из окна;
  - сортировка по `|ten − T|`, при равенстве — новее выше.
- **Новый эмитент:** 8 сделок выбранного типа из окна, та же сортировка.
- Колонки: дата, эмитент (у своих — пометка «· свой выпуск»), выпуск, срок, ставка, спред, спрос к предложению, доля физлиц, источник (ссылка «KASE ↗»).

### 3.9 Покупатели похожих выпусков
По сопоставимым сделкам, где `src` не null, считаем среднее каждой категории (null = 0). Показываем горизонтальную полосу-стек и легенду с процентами. Подпись: «Средние доли по {n} сделкам из списка ниже, где KASE раскрыла покупателей. Больше всего — {категория}.»

### 3.10 Статус «окна»
- `withCov` — сделки с `cov`; `under` — из них с `cov < 99,95`.
- Статус:
  - «мало сделок», если `withCov < 3`;
  - иначе считаем `доля = under / withCov`:
    - «закрыто», если `доля ≥ 1/3`;
    - «открыто», если `доля ≤ 0,15`;
    - иначе «нейтрально».
- Пороги — допущение команды, это так и написано на экране.
- Иконки:
  - открыто — зелёный круг с галочкой;
  - нейтрально — серый круг с минусом;
  - закрыто — красный квадрат с крестом;
  - мало сделок — пустой круг.

### 3.11 Плитки «Рынок сейчас»
- Размещений — число строк `deals`.
- Привлечено — Σ`vol`, в трлн ₸.
- Медиана спроса к предложению — медиана `cov`.
- Сделок с недобором — `under / withCov`, с подписью «(34 из 167)».
- Сделок, где все заявки по одной ставке — доля сделок с `bmin = bmax`. Берутся сделки, где `bmin`, `bmax`, `fin` не null и `knd ≠ маржа`.

### 3.12 Окно по месяцам и по типам
- **По месяцам:** для каждого месяца — число сделок, объём, медиана `cov`, недобор «x из y» и статус (3.10). Октябрь подписан «Октябрь (1–19)».
- **По типам за 90 дней:** сделки с `d > asof − 90 дней`. Колонки:
  - размещений;
  - объём;
  - медиана спроса;
  - с недобором;
  - медианный спред за 90 дней;
  - спред за год (`p50` из 3.3);
  - окно.

### 3.13 Проверка на истории
- `btStat(key, filter)`: строки `bt`, где `key` не null и выполняется фильтр.
  - Ошибка = `|rate − key|`.
  - Выводим `n`, `MAE` (средняя ошибка) и долю строк с ошибкой `≤ 0,5`.
- Плашки (доля попаданий в ±0,5 п. п.):
  - B — «Медиана ставок того же типа за 180 дней»;
  - A — «ГЦБ того же срока + медианный спред типа»;
  - D — «Compass: ГЦБ + прошлый спред эмитента».
- Таблица MAE:

| Строка | Метод | Фильтр |
|---|---|---|
| Все 110 | B | — |
| Все 110 | A | — |
| Все 110 | D | — |
| Повторные эмитенты: прошлый купон | C | `own` |
| Повторные эмитенты: прошлый спред + кривая | D | `own` |
| Новые эмитенты: ГЦБ + спред типа | A | `!own` |

- Точечный график: x — D, y — rate. Цвет точки: `own` → категория 1, новый → категория 2. Диагональ и полоса ±0,5 п. п.

### 3.14 «Липкий» купон
- Из `stick`: всего 27 из 81 нового выпуска (33%) вышли с купоном прошлого выпуска эмитента.
- У частных эмитентов (лизинг + МФО + корпорации) — 13 из 14.
- У международных финорганизаций — 0 из 9.
- Подпись: «Доразмещения уже обращающихся выпусков и транши в один день не учитываются.»

### 3.15 Проверка без повторных размещений
- В строке `bt` поле `seen` = в `deals` есть сделка того же эмитента с тем же `tk`, со `spr` и с датой раньше `d`.
- Таких строк 23. На остальных 87: D — 57% в ±0,5 п. п., B — 40%. Это фраза под таблицей MAE.

### 4.1 Ориентир купона (`#guide`, открыт по умолчанию)
- **Заголовок:** «Ориентир купона для нового выпуска».
- **Лид:** «Выберите эмитента, срок и объём. Compass берёт доходность ГЦБ того же срока на 19.10.2026 и спреды прошлых размещений на KASE, показывает похожие сделки, их покупателей и цену выпуска в деньгах.»

  - переключатель «Уже был на KASE / Новый эмитент»;
  - эмитент (select) или тип эмитента (select);
  - срок, лет: число 0,5–15 с шагом 0,5 и быстрые кнопки 1 год / 2 года / 3 года / 5 лет;
  - объём, млрд ₸;
  - подсказка: «Дата расчёта — 19.10.2026, последние данные в базе. Тенге, фиксированный купон.»
- **Результат справа:**
  - надпись «ОРИЕНТИР КУПОНА НА 19.10.2026»;
  - крупно коридор «18,9–20,0% годовых» (одна цифра после запятой);
  - чипы:
    - точность («На истории: ошибка до 0,5 п. п. в 64% случаев» или для нового — «Новые эмитенты: средняя ошибка на истории 2,3 п. п.»);
    - «ГЦБ 2 года: 15,17%»;
  - список фактов:
    - доходность ГЦБ с подписью о кривой;
    - прошлый выпуск;
    - сохранить прошлый спред;
    - повторить прошлый купон;
  - для нового эмитента вместо прошлого выпуска — спред типа p25…p75 и медиана;
  - плашка (3.4 или 3.5);
  - строка про деньги (3.6);
  - кнопка «Скопировать обоснование».
- **Кнопка «Скопировать обоснование».** Копирует текст в буфер (`navigator.clipboard.writeText` внутри обработчика клика, при ошибке — запасной вариант через textarea). Состав текста:

  - ориентир;
  - ГЦБ;
  - прошлый выпуск или спред типа;
  - список сопоставимых сделок со ссылками;
  - последняя строка «Статистика прошлых размещений KASE, не инвестиционная рекомендация.»
- **Ниже в две колонки:** «Сравнить два варианта выпуска» (3.7) и «Кто покупал похожие выпуски» (3.9).
- **Ниже:** таблица «Сопоставимые размещения» (3.8).

### 4.2 Рынок сейчас (`#market`)

## 5. Правила интерфейса
- **Формат чисел** — `toLocaleString('ru-RU')`. Спреды со знаком: «+3,72», «−0,07» (минус — типографский «−»). Проценты с одним знаком после запятой там, где так в эталоне.
- **Суммы** в ₸, млн ₸, млрд ₸, трлн ₸. Доллары не показываем, они уже пересчитаны по 475,09 ₸.
- **Ссылки на источники:**
  - каждая сделка — `https://kase.kz/ru/information/news/show/{id}`;
  - общий источник в подвале — итоги KASE за 9 месяцев: https://kase.kz/uploads/15_10_2026_Itogi_3q_rus_3609a63a33.pdf
- **Графики:**
  - тонкие марки, скругление 4 px у концов столбцов, 2 px зазор между сегментами стека;
  - сетка приглушённая, одна ось Y, без двойных осей;
  - подсказка при наведении и при фокусе с клавиатуры;
  - область наведения больше самой марки (не меньше 24 px).
- **Статус окна** — всегда иконка и слово, не только цвет.
- **Пустые состояния:** если по сделкам нет покупателей — «По этим сделкам KASE не раскрыла покупателей.»; если в фильтре срока нет сделок — «нет сделок с таким сроком».
- **Мобильная версия (390 px):**
  - форма над результатом, две колонки складываются в одну;
  - вкладки прокручиваются вбок;
  - страница целиком не прокручивается по горизонтали.
- **Тёмная тема** — если сайт её поддерживает, все цвета берутся из токенов темы.
- **Дисклеймер в подвале (дословно):** «KASE Compass — учебный концепт-прототип для кейс-чемпионата KASE. Это не официальный сервис KASE и не инвестиционная рекомендация: все цифры — статистика прошлых размещений.»
